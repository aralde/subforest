# Decisions

One line per decision: date — decision — reason.

- 2026-10-20 — Node and chunk ids are integers; agents see them as `n<id>` (`Node.short_id`) — simplest stable short id that maps 1:1 to the SQLite primary key.
- 2026-10-20 — `TreeStore` uses parent pointers + a recursive CTE for ancestors (no closure table) — trees are shallow and writes stay trivial; revisit only if ancestor queries show up in profiles.
- 2026-10-20 — `ancestors()` returns root → parent, excluding the node itself — matches the breadcrumb order `read` will print.
- 2026-10-20 — Models are frozen pydantic models with `extra="forbid"` — immutable values are safe to share between store, induction and tools.
- 2026-10-20 — Docstring examples run as doctests (`--doctest-modules`) — keeps the "every public function has an example" rule honest.
- 2026-10-20 — Fixture corpus describes a fictional product ("Larch") — no third-party content, no license questions.
- 2026-10-20 — A leading H1 (no content before it) becomes the doc title and is not a section; front-matter `title:` wins over it — avoids a doc whose only child is a section repeating its name.
- 2026-10-20 — Front matter is parsed for `title:` only, without a YAML dependency — keeps the core dependency-free; revisit if more keys matter.
- 2026-10-20 — Only ATX headings (`#`) are parsed; setext headings and headings inside fenced code are ignored — ATX covers the docs sites we target and keeps the parser small.
- 2026-10-20 — Chunk `start`/`end` are offsets into the whole document; each node only chunks the text between its heading and its first child heading — chunks never cross a section boundary by construction.
- 2026-10-20 — Chunks pack whole paragraphs up to `max_chunk_chars` (default 1000), hard-splitting longer paragraphs at the last space — simple, deterministic, no tokenizer dependency.
- 2026-10-20 — Directory builds sort entries by path; sitemap builds keep sitemap order — the sitemap order is the author's intended order, the filesystem has none.
- 2026-10-20 — Sitemap docs read text from `<path>.md|.mdx` or `<path>/index.md|.mdx` next to the sitemap, resolved inside that root — offline builds, no fetching, no path escape.
- 2026-10-20 — `subforest build` refuses an existing `--db` unless `--force` (which replaces it) — no silent merges of two builds into one database.
- 2026-10-20 — `llms.txt` builder deferred (listed in CLAUDE.md, not in M1's plan) — will add when a target corpus needs it.
- 2026-10-21 — FTS5 index is contentless (`content=''`), indexes node title + chunk text with the porter tokenizer, and rebuilds when its row count differs from `chunks` — titles carry most of the structure signal; rebuild-on-mismatch keeps it simple without triggers.
- 2026-10-21 — Free-text queries become quoted terms OR-ed together; score is `-bm25()` rounded to 6 decimals, ties broken by chunk id — no FTS syntax errors from user input, deterministic ranking for goldens.
- 2026-10-21 — `SubForest` gains optional `scores` and `child_counts` (defaults empty) — render needs hit strength and collapsed-sibling counts without touching the store; existing callers are unaffected.
- 2026-10-21 — Hit markers show subtree totals on doc and section lines only, capped at 5 dots — a doc's line summarises its sections; dirs stay unmarked as in the rendering contract.
- 2026-10-21 — Budget collapse order: weakest leaf sections (keep ≥1 per doc) → weakest whole docs (footer count) → strongest doc's sections; below the minimal view the minimal view is returned — collapse instead of truncate, and never return nothing.
- 2026-10-21 — Weakness = (summed BM25 score, hit count, newer id first) — uses only what the retriever gives us; deterministic.
- 2026-10-21 — Default token estimator is `ceil(chars / 4)`, pluggable via `estimator` — no tokenizer dependency in core.
- 2026-10-21 — Added `subforest search "<query>" --db … --budget N` to the CLI — quickest way to eyeball the view an agent gets; `build` now also creates the FTS5 index.
- 2026-10-21 — Builds store each document's full source text (`doc_texts` table); `read` slices it by the node span — sections come back with their headings, and tools never open files, so path arguments cannot reach the filesystem.
- 2026-10-21 — Tools accept node ids as `n31`, `31` or `31` (int), and documents also by corpus-relative path (looked up in the DB; `..`, absolute, `~` and drive paths rejected) — agents copy ids from the outline; paths help when they know a file.
- 2026-10-21 — Tool errors and policy blocks are returned as `ToolResult(error|blocked=True)` with an instructive text, never raised through `Toolkit.call` — the agent can recover in its next step.
- 2026-10-21 — Policy rules are scoped to the current turn (`Toolkit.new_turn()` resets); blocked calls do not count as calls — matches "per-turn state" in the plan; keeps rules predictable.
- 2026-10-21 — Cooldown means "N other calls since the last use of the tool" — expresses "inspect results before searching again" without timestamps.
- 2026-10-21 — Harness tools (e.g. `semantic_search`) plug in via `Toolkit(extra_tools=…)` so the same policy governs them — the "read before semantic search" example needs a tool subforest does not ship.
- 2026-10-21 — YAML policies need the `subforest[yaml]` extra (PyYAML); JSON works with the core install — keeps the core free of non-stdlib parsers beyond pydantic.
- 2026-10-21 — `search(more_results=True)` uses `more_k` hits (default 30) and twice the render budget — the footer promise "more docs with weaker hits" must actually surface them.
- 2026-10-21 — `read` over budget: node's own text + list of subsections; if still too long, cut at a paragraph boundary with an explicit note — collapse first, truncate only as a last resort and say so.
- 2026-10-21 — `expand`/`outline` show `(+N)` for children beyond the shown depth and reduce depth until the view fits the budget — same collapse-not-truncate rule as `render`.
- 2026-10-21 — MCP server built on `mcp>=2.3` (`MCPServer`, stdio) in the `subforest[mcp]` extra; tools are registered as `async` functions — mcp 2 runs sync tools in worker threads, and the SQLite connection belongs to the serving thread.
- 2026-10-21 — MCP tool results carry the text both as text content and as `structuredContent.text` (plus the JSON payload); errors and policy blocks set `isError` — the Claude Code smoke test showed the client passes only structured content to the model when present.
- 2026-10-21 — MCP policy turns reset after `--turn-idle-seconds` (default 120) without calls — MCP has no turn boundary; an idle gap is the simplest proxy.
- 2026-10-21 — CI installs all extras (`uv sync --all-extras`) so mypy and tests cover the MCP server — extras stay optional for users.
- 2026-10-21 — M4 smoke test (Claude Code 2.1.299, `claude -p --mcp-config`, fixture corpus): all 5 tools listed; search → read n30 → expand n29 → read n24, n34; answered "90 days; create new, deploy, revoke old" with citations. First run failed (model saw only structured payload without text) — fixed as above, then passed.
- 2026-10-28 — M5 narrowed to a WixQA replication (200 questions, Haiku 5.5 via API) — the paper already validates the approach; our eval checks this implementation under our conditions.
- 2026-10-28 — Eval data lives under `$SUBFOREST_DATA` (default `~/.cache/subforest/datasets`); only download code, normalized formats and reports are in the repo — dataset rule from CLAUDE.md.
- 2026-10-28 — WixQA tree = article type → product (title prefix, " Request" suffix merged) → article; HTML converted to Markdown with a stdlib parser — the help center has flat URLs and no sitemap in the dataset; no new dependency.
- 2026-10-28 — QASPER uses the test split only (416 papers) as the corpus; evidence paragraphs are located by exact substring in the rendered Markdown — smallest corpus with human evidence labels; exact matching avoids fuzzy false positives.
- 2026-10-28 — Coverage compares first views at equal estimated tokens: chunks = top-k chunk texts (with a title line) until the budget is full; subforest = rendered view. Evidence counts for subforest only if a shown node contains it and fits one `read` (≤ 800 tokens) — makes the "one extra call" asymmetry explicit instead of hiding it.
- 2026-10-28 — QASPER coverage reported for raw and title-prefixed questions — raw QASPER questions are ambiguous across 416 papers; both numbers are shown rather than picking the flattering one.
- 2026-10-28 — Tier 2 gate passed (subforest ≥ chunks on doc coverage everywhere, on evidence when the question is specific) — proceed to tier 3.
