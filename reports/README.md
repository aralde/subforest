# Reports

Generated by `subforest bench` / `subforest coverage` (see `docs/datasets.md`). Numbers below are from
2026-10-28, BM25 top-50 hits, default render.

## Tier 1 — scale

Both corpora build deterministically (identical databases on two builds). WixQA (6,221 docs, 32,597 nodes)
builds in ~7.5 s into a 46.5 MB database; search + induce + render takes ~80 ms p50 and ~135 ms p95 per query.
Details: [wixqa-bench.md](wixqa-bench.md), [qasper-bench.md](qasper-bench.md).

## Tier 2 — what the first view contains, at equal token budgets

| Budget | WixQA gold doc (chunks → subforest) | QASPER evidence, raw question | QASPER evidence, titled question |
|---|---|---|---|
| 250 | 28.0% → **57.5%** | 5.7% → 8.1% | 1.3% → 8.6% |
| 500 | 42.5% → **70.5%** | 11.5% → 10.2% | 9.5% → 12.5% |
| 1000 | 60.5% → **76.5%** | 19.5% → 18.0% | 28.0% → **43.1%** |
| 2000 | 68.0% → **82.0%** | 26.2% → 31.5% | 46.2% → **58.9%** |

Reading it:

- At the same budget, the sub-forest shows the right **document** far more often (WixQA: 1.2–2× as often), because
  a line per document is cheaper than a chunk per document.
- For **evidence**, the arms are not symmetric: chunks show the text itself, the sub-forest shows where it is and
  needs one `read`. Even so, when the question identifies the paper (titled), the sub-forest locates the evidence
  section 3–15 points more often. With ambiguous raw QASPER questions the two are roughly tied.
- This is retrieval only. Whether the agent turns better coverage into better answers is tier 3.

[qasper-coverage-titled.md](qasper-coverage-titled.md).

## Tier 3 — agent pilot, 50 WixQA questions (Haiku via `claude -p`, no spend)

| Metric | chunks | subforest | Paired Δ (95% CI) |
|---|---|---|---|
| Saw gold-doc text | 84.0% | 72.0% | −12.0% (−24.0% to 0.0%), sign test p = 0.11 |
| Gold doc shown by any call | 84.0% | 80.0% | −4.0% (−14.0% to +6.0%) |
| Answer token F1 vs reference | 0.387 | 0.397 | +0.010 (−0.022 to +0.039) |
| Tool calls / input tokens (mean) | 2.2 / 9.6k | 3.9 / 15.2k | |

Reading it:

- **No advantage for the sub-forest in this pilot.** Answer overlap is tied; the agent reached gold-doc text
  slightly less often (not significant at n = 50) and spent ~1.7 more calls and ~60% more input tokens.
- The tier 2 gain (gold doc visible more often) did not carry over: in several misses the gold doc was in the
  outline but Haiku chose to read a sibling with a similar title. WixQA articles are short and the tree is shallow
  (type → product → article), so there is little intra-document structure to navigate.
- This does not contradict the paper (different model, retriever and answer-accuracy metric), but we make no
  accuracy claim. Per the stop rule, any further render iteration must beat chunks beyond the CI.

## Tier 3 — agent pilot, 50 QASPER questions (titled, Haiku via `claude -p`, no spend)

One question per paper, only questions with located evidence, the paper title named in the question.

| Metric | chunks | subforest | Paired Δ (95% CI) |
|---|---|---|---|
| Saw gold evidence | 68.0% | **90.0%** | **+22.0% (+6.0% to +36.0%)**, 14 / 3 discordant, sign test p = 0.013 |
| Saw gold-doc text | 100.0% | 100.0% | — |
| Answer token F1 vs reference | 0.089 | 0.089 | +0.000 (−0.017 to +0.019) |
| Tool calls / input tokens (mean) | 2.6 / 13.9k | 4.1 / 18.5k | |

Reading it:

- **Where documents are long and sectioned, the sub-forest helps the agent find the evidence**: it reached the
  gold evidence paragraph 22 points more often, significant even at n = 50. This matches the tier 2 result and
  the direction of the paper's QASPER ablation.
- It costs ~1.5 more calls and ~33% more input tokens; part of the gain may come from reading more text.
- Token F1 is uninformative here (both 0.089): Haiku writes full sentences while QASPER references are short
  spans. Whether finding the evidence improves answers needs a judge, which we have not run.
- Contrast with WixQA (short, flat articles): no gain there. Structure pays off where there is structure.

File: [qasper-agent.md](qasper-agent.md).

## Tier 3 — judged answers (Sonnet judge via `claude -p`, blind to the arm)

The judge was checked on 40 QASPER answers sampled with a fixed seed and labelled blind in-session by Claude
Opus (a model, not a human): Sonnet agreed on 97.5% (correct vs not), Haiku only on 77.5%, so Sonnet judges.

| Dataset (50 questions) | Judged correct: chunks → subforest | Paired Δ (95% CI) | Correct or partial |
|---|---|---|---|
| WixQA | 72.0% → 70.0% | −2.0% (−14.0% to +10.0%) | 92.0% → 92.0% |
| QASPER, titled | 52.0% → 52.0% | +0.0% (−12.0% to +12.0%) | 66.0% → 68.0% |

Reading it:

- **Answer accuracy is tied in both datasets.** On QASPER the sub-forest found the gold evidence 22 points more
  often, but Haiku turned that into the same number of correct answers.
- At n = 50 the CI is ±12 points, so we can rule out large effects, not the paper's +2.4 to +10.5 points.
  Detecting those would take several hundred questions per dataset.
- Our claim stays at what we measured: the sub-forest helps the agent **locate evidence** in long, sectioned
  documents, at ~1.5 more tool calls. We make no answer-accuracy claim.
